# Qwen 对照：实测结论与可用表达

## 已完成的证据工程

2026-10-23 完成两轮真实调用。两批各 60 条 AI 辅助构建、预先标注的合成场景，共 120 条；v1 五组包含两项消融，v2 使用三组主对照；合计 480 条完整观测、452 次真实模型请求。剩余 28 条为 Agent 的本地澄清路径，不冒充模型调用。

冻结协议记录模型标识 `qwen3.7-plus`、数据/源码 SHA-256、温度 0、并发 2、调用上限和场景标签。所有模型组获得同一任务提示、相同可用资料和同一观测契约；预设标签不进入请求。用量来自供应商 usage，无缺失；逐题原始结果、失败、P50/P95 和配对区间均保留。v1 的旧源码已存快照，后续修复不覆盖首次证据。

| 引用判断符合预设标签 | 58/60 | 56/60 | 53/60 |
| 错误绑定 | 0/60 | 0/60 | 0/60 |
| 明确日期匹配 | 20/22 | 20/22 | 20/22 |
| 模型调用 | 60 | 60 | 52 |
| 输入 Token | 100,921 | 100,921 | 83,351 |
| 总 Token | 112,073 | 112,060 | 92,528 |
| 全观测文本处理均时（秒） | 3.873 | 3.893 | 3.222 |
| 全观测 P50 / P95（秒） | 3.872 / 4.583 | 3.863 / 4.658 | 3.709 / 4.518 |

相对直接 Qwen，当前 Agent 输入 Token 少 17.41%、总 Token 少 17.44%、模型调用少 13.33%。结构化通过率同时低 10 个百分点，不能据此声称整体性能优于 Qwen。

在两组**都符合结构化标签的同一批 50 题**上，文本处理均时从 3.886 秒到 3.289 秒，减少 15.36%；它是条件子集的单轮描述，不替代全量质量。耗时不含采音、ASR、手语生成或渲染。未按 Token 数直接计算费用，供应商前缀缓存与网络也会影响结果。

通过率差的案例配对 bootstrap 区间见原报告。合成案例存在模板/领域相关性，且标签未经独立人工复核；这些区间不外推真实用户总体。

## 质量损失来自哪里

- **过窄的文本召回**：中英文事项别名、不同量词和同义表述无法总由当前有限词表覆盖；一旦过滤掉记录，后面的 Qwen 也拿不到对应 ID。
- **话题连续性判断过硬**：简短承接词可能被当作话题中断；有日期变更但未命中特定更正标记时，近期话题未被采用。
- **过早本地澄清**：部分可借助上下文消歧的输入被本地规则挡住，节省调用的同时损失了覆盖。
- **行动契约仍需核验**：模型可能将未满足前提保存为未来行动；“提醒”与待办草稿的边界也存在产品策略歧义。该批预设标签保留，不事后删题或改分。

v1 中已发现并修复的常见量词指代、口头更正和问句草稿问题，有独立单元回归；新集又暴露了更广泛的覆盖缺口，说明仅扩展关键词不足以证明泛化提升。后续值得比较的是软排序、低置信回退、跨语言召回与模型引用核验，而不是继续用硬过滤替代模型的全部理解能力。本轮没有为获取更高分继续生成第三批测试集。

## 简历与 GitHub 的表达

当前可直接采用的工程成果：

> 构建基于 Qwen 的记忆增强交流 Agent 与可复现评测工程，设计两批共 120 条冻结合成场景、三组主对照及两项消融，完成 480 条观测；沉淀真实 Token、P50/P95、源码与数据指纹、离线重评分和失败归因，并配置无收费调用的 GitHub CI。

如果引用当前效率数字，需要同时说明覆盖退化或直接链接全量质量结果；本轮不支持“准确率提升 X%”“在相同质量下降低成本”或“整体优于 Qwen”。实际账单费用和真实用户理解度没有测量。

关于 vivo / 百度，当前可写：

> 调研 vivo 与百度公开的手语数字人分层链路，在交流上下文检索、记忆指代与可撤销语义提交方面进行独立实现和评测。

本项目没有取得并修改它们的闭源算法，也没有同条件运行其产品。当前事项结构化指标不能与手语可懂率、赛事分数或动作延迟换算。[公开研究依据](research-basis.md)。
