# SIGNOVA 评测的公开研究依据与比较范围

核验日期：2026-10-23。本文说明公开研究与本项目的关系；研究参考、独立实现、产品对测分别记载。性能结论以本仓库每次实验的输入、输出、配置及报告为准。

## 1. 两条评测线分别回答什么

**交流 Agent 评测**回答：在同一 Qwen 模型和同一任务输入下，事项检索、指代消歧、版本处理与确认策略，能否改善事项决策、事实保真、错误更新、延迟和用量。这是当前可以直接开展的对照实验。

**手语生成评测**回答：普通语言是否被正确转换成特定手语，数字人的手型、位置、朝向、运动、非手控信息是否可理解。这需要手语参考数据、完整动作输出和有资格的语言评审。交流 Agent 的事项正确率不能替代手语可懂率；候选分析提前量不能替代数字人播放延迟。

本轮发布聚焦交流 Agent 的代码、数据与评测；数字人动作预览不在本轮质量指标中，不能由事项结构化结果推导完整手语翻译能力。

## 2. 用户此前提供的两篇论文分别是谁的

### 2.1 vivo：维沃手语数字人翻译系统

作者单位为维沃移动通信有限公司。方向是汉语文本到中国手语数字人生成，链路包含手语文本翻译、动作融合与面部驱动，属于生成方向，并非仅从手语视频识别文字。论文第 2 节使用 mRASP、伪平行语料及回译；第 3 节研究多帧平滑与基于 Transformer 的速度调节。官方赛事综合分为 3.513，论文自测的词可懂率 96.82% 使用另一套自建数据及人工评测，二者各有独立口径。[原论文 PDF](https://aclanthology.org/2024.ccl-3.43.pdf)、[论文元数据](https://aclanthology.org/2024.ccl-3.43/)

**对 SIGNOVA 的启发**：将文字决策、动作连接、节奏和非手控表达分别验证。当前事项记忆模块没有训练该论文的翻译模型，也没有实现其速度网络；两者的模型结构、输出和评测任务不同。

### 2.2 果不其然 / 北京交通大学：结合 LLM 与 3D 动画技术的手语数字人系统

作者单位为果不其然无障碍科技（苏州）有限公司和北京交通大学，**不是百度论文**。方法是利用格式化的中文—Gloss 样例做上下文学习，再驱动手语、表情和口型通道；文中比较通义、文心和星火，涉及自动文本指标与人工动作评审。其后续研究建议包括规范词库、语境检索及纠错，不能据此推断均已实现。[原论文 PDF](https://aclanthology.org/2024.ccl-3.44.pdf)、[论文元数据](https://aclanthology.org/2024.ccl-3.44/)

**对 SIGNOVA 的启发**：将检索与约束放在 LLM 调用的上下游，并通过消融实验检验收益。本项目的任务是事项理解；其记录检索没有等同于论文中的 Gloss 示例库或权重训练。

## 3. 百度曦灵公开披露了什么

百度智能云 2022 年官方发布披露：语音识别、精炼度可控的神经手语翻译及动作融合；自然手语标注语料用于语序、映射与长度处理。官方案例将过程分为语音到汉语文本、文本到手语码、手语码到数字人动作，并提及二维骨骼到三维驱动。这些是产品方历史披露，未在本文核实其当前全部内部实现。[平台发布](https://cloud.baidu.com/news/news_14b483c5-d512-48fd-9e9b-be7325665152)、[AI 手语主播案例](https://cloud.baidu.com/customer/case/shouyuzhubo.html)

**对 SIGNOVA 的启发**：任务语义保真和动作质量应分层测量；精简表达仍需保留否定、日期与条件。本项目没有取得或修改曦灵模型、训练语料或闭源引擎，现有 Agent 指标也不构成曦灵产品对测。

核验时搜索到百度开发者中心的多篇文章，但域名承载投稿本身不足以确认作者身份及指标口径。本文件采用可确认的百度智能云官方发布；未将未经独立验证的“300ms”“毫米级”“百分之百匹配”等搜索片段写为技术事实。

## 4. 流式处理的公开参考与复现等级

| 参考 | 公开方法 | 与当前 SIGNOVA 的关系 |
| --- | --- | --- |
| Whisper-Streaming（Macháček 等，2023） | 对多次识别结果使用 LocalAgreement，构建实时转写 | 本项目借鉴“重复观测后再提交”的思路；当前实现还加入分句边界、风险等待及撤销。未运行其 Whisper 音频解码、缓冲裁剪与自适应流程，属于受启发的任务策略 |
| SimulEval（Ma 等，2020） | 对同时翻译共同评估质量与延迟，按读取/写出事件记录策略 | 当前回放沿用事件可追踪的评测思想，未接入该工具包；自定义候选提前量不是 AL、DAL 或论文原报告成绩 |

参考：[Whisper-Streaming 论文](https://aclanthology.org/2023.ijcnlp-demo.3/)、[作者代码](https://github.com/ufal/whisper_streaming)、[SimulEval 论文](https://aclanthology.org/2020.emnlp-demos.19/)、[官方代码](https://github.com/facebookresearch/SimulEval)。

若后续新增“LocalAgreement 风格”对照，应公布比较的是源文本假设的公共前缀还是实际音频重复解码，并公开分词、提交窗口和异常处理。只有同原算法、同输入过程及合理配置的实现才标记为忠实复现。普通固定等待、整句等待、反复相同前缀等独立实现使用对应的描述性名称。

## 5. 当前能做、值得做的实验

### Qwen Agent 对照

1. 直接 Qwen：同一版本模型，获得同一任务说明、当前发言、允许使用的原始记录及近期对话，由模型直接作出结构化决策。
2. Qwen + 普通关键词检索：保留相同模型与任务输出规范，只改变输入记录的筛选。
3. 完整 SIGNOVA Agent：相同信息权限，增加版本过滤、话题与指代判断、歧义澄清及结果约束。
4. 消融：分别移除指代判断、版本过滤、歧义门控或结果约束，以估计各模块贡献。

报告全样本任务成功率，并同时报告绑定精度、绑定覆盖率、漏绑定、错误绑定和过度澄清。Agent 通过本地判断跳过模型时，调用数及耗时如实计入系统指标；模型调用子集的耗时单独报告，以免把少调用解释成模型本身推理更快。输入 Token、输出 Token、请求失败、重试、P50/P95、置信区间与失败实例随结果保留。

直接 Qwen 组提供足够明确的指令和相同可用信息，避免使用弱提示词构造有利对照。数据按场景/模板家族隔离开发与测试，独立测试前冻结版本；复用开发样本得到的结果标为开发集结果。

### 流式策略对照

使用同一组带时间戳的识别假设，对比整句等待、固定等待、公共前缀风格策略及完整 SIGNOVA 策略。记录首次候选、首次正确候选、撤销次数、错误候选暴露时间、最终信息保留和模型调用数；真实语音与合成事件分开报告。

### 动作融合研究的后续条件

若取得适用许可的完整动作数据，可独立实现简单线性/球面插值作为对照，再评估时间对齐、接触约束和局部关节分组的收益。几何指标包括位置/旋转误差、跳变、速度、加速度、接触偏差等；语言质量另由手语使用者或译员评审。该实验完成前，动作融合相关内容属于研究方向，当前 Agent 评测不会产生动作算法的收益数字。

## 6. 什么结果可以支持哪种表达

| 证据 | 可采用的成果表达 |
| --- | --- |
| 同模型、同任务、同信息权限的真实 Qwen 对照 | “相较直接调用同一 Qwen 模型，SIGNOVA 在指定测试集上将事项决策成功率由 A 提升至 B” |
| 公开描述的策略被独立实现并以同样事件测量 | “参考公开流式研究，设计风险感知提交；相较本仓库的某策略实现，指标改善 X” |
| vivo / 百度资料仅用于架构调研 | “调研 vivo、百度的手语数字人分层链路，在交流上下文与可撤销语义提交方面开展独立优化” |
| 动作或译文未使用相同授权数据、评审及指标 | 使用各自范围的说明，暂不生成跨产品优劣结论 |

现有证据没有建立“修改了 vivo / 百度的算法实现”或“整体优于其产品”的结论。要得到此类结论，需要可访问的指定版本、相同输入输出、适用授权及同条件评审；论文自测百分比、赛事人工分和本项目事项正确率不直接换算。

## 7. 手语质量评审参考

QESLAT-2024 组织者材料把汉语到中国手语数字人的质量交由聋人及专业译员人工评测；公开排名也确认 vivo 与果不其然的不同归属。它可以作为后续语言评审设计参考，不代表本项目参与赛事、获得其数据授权或已复现排名。[评测组织者仓库](https://github.com/ann-yuan/QESLAT-2024)
