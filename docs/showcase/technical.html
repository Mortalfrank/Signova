SIGNOVA / ENGINEERING CASE STUDY

让交流可以继续，
需要怎样的技术设计？

从一次校园办理出发，连接上下文、本人表达与可更正的事项记忆。把模型能力放进一个可以核对、确认和继续使用的流程。

01 / THE PROBLEM

字幕之后，还有一件事要办。

校园窗口的交流经常包含材料、时间、地点和下一步。字幕解决眼前的信息传递，但用户还需要提问、记住要求，并在再次办理时接上此前的沟通。

SIGNOVA 面向聋人及听障用户，把体验组织为“理解现场、本人表达、跨次接续”。项目的技术重点，是组织现有模型、资料和用户状态，让建议有上下文，让表达与记忆更新有确认步骤。

保留原话→生成候选→本人确认→事项接续

02 / THREE DESIGN DECISIONS

三个决定，贯穿整个流程。

A

模型提出候选，操作交给用户。

后端通过兼容接口调用千问，输入当前发言、最近最多六条会话发言和启用的资料。输出限定为回复、事项草稿、更新目标及确认说明，并校验结构、长度与事项引用。

用户选择或编辑回复，确认后才对外展示或播放；事项同样需要核对后保存。模型不能因为识别到“改为周五”，就直接覆盖所有记录。指代不明确时先询问，保留用户纠正的入口。

资料采用有限文本进入上下文，当前没有部署多文档向量检索系统。实际模型结果与规则回退使用不同来源标识，避免把故障后的模板回复当成模型输出。

模型接口与输出校验 ↗
B

记忆保存最新事实，也保留变化。

事项记录名称、待办、截止时间、状态、原话来源和更新时间。周三改为周五时，更新同一事项的当前版本；旧内容进入历史列表，供用户追溯。

用户允许模型参考记忆后，代码按文本与事项内容的词项重合度、更新时间选择最多六条最新事项。历史版本不进入这次模型上下文，场景资料也不混作个人事实。

数据保存在当前浏览器。继续办理页的基础回复来自已确认字段组成的规则模板；交流页启用模型和记忆权限后，才会生成带事项上下文的模型建议。这是可更正的状态管理，不是持续训练模型。

事项上下文选择 ↗
C

数字人的语言与动作分层处理。

语音识别和通用文本模型不能保证手语表达正确。SIGNOVA 将字幕、语言词目匹配、动作来源、骨架适配和播放器分开，避免把角色能动当作语言准确。

NOVA 使用五十根骨骼，包含双手三十个指节。动作管线处理目标骨架重定向、腕部约束、手掌与指节方向，并检查数值连续性；播放器提供重播、慢放、定位和放大查看。

中国手语来自公开词目视频的本地关键点估计，ASL 来自公开动捕 FBX。前者仍有深度与遮挡不确定性，两类数据在适配后都需要视觉检查和语言评价。

03 / EVIDENCE

用一次真实更正，验证记忆接续。

本次在本机使用虚构校园事项和文字输入，完成真实千问调用：提取提交实习证明的候选事项，经确认保存；输入更正后，模型建议更新原事项为周五。再次确认后，历史仍保留周三前，刷新页面也能读取周五的新状态。

输入与结果真实模型调用、本人确认、同一事项更新、历史保留、刷新后接续。

验证条件更正期间一次网络请求失败，重试后成功。剪辑时长不作为接口延迟；此次文字链路不代表麦克风实录、跨设备同步或手语理解度验收。

自动化检查验证结构、状态和语言目录隔离；真实接口验证服务可调用；交互验证确认和更正能走通。手语是否可理解，需要目标用户或专业人士参与评价，不能用工程测试项数替代。

04 / IMPLEMENTATION & RESEARCH

每层能力，有各自的验证标准。

当前已连接手机交互、可配置的模型与语音接口、回复和事项确认、浏览器内版本化记忆及独立动作管线。模型与语音需要有效配置和主动启用；麦克风还依赖权限与安全连接。

动作目录提供中国手语“停止”和 ASL 的 Hello、Please、You 四个待核验词汇，按语言分开。当前没有任意句子的连续手语翻译、账户鉴权及跨设备同步。

下一步集中在场景内完整表达、手部接触与拓扑、面部语言通道，以及手语使用者的可理解性验证。预渲染片段可作为呈现选择，但同样需要语义对应和来源记录。
