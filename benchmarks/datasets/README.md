# SIGNOVA Communication v1 自建评测集

本目录提供 **60 条 AI 辅助构建的冻结合成场景与预设标签**，用于比较直接调用同一模型与增加记忆处理策略后的系统行为。这些数据由本次 AI 辅助开发流程构建，尚未经独立人工复核；它是自建开发评测集，不是独立盲测、公开标准测试集或真实用户采样。

- 文件：`communication-v1.jsonl`，每行一个完整样本，UTF-8，无空行。
- 版本：`communication-v1`；固定评测时刻：`2026-10-23T00:00:00Z`（由 runner 注入，不使用系统当前日期）。
- 冻结 SHA-256：`1eff6ec5559a8e1bf054df0b7125a0f0e9ffadf269a9533194559103eeae2f1d`。
- 冻结方式：先完成样本与标签，再运行模型；未调用模型或运行事项解析器来筛题、调标签。后续修订应另起数据版本并说明原因，保留本版本结果。
- 数据来源：AI 辅助构建的合成场景与预设标签，没有真实姓名、账号、病历、录音、用户对话或企业内部资料；不视为独立人工标注的标准答案。
- 字段上限：每例最多 6 条原始事项，当前文件实际最多 5 条。原始记录可含同编号旧版本或另一演示档案；两组系统应使用同样的档案过滤和最新版本前处理规则。

## 每行 schema

```text
{
  id, split: "test", domain, category, text, knowledge,
  context: [string],
  profile: "personal" | "visitor",
  memoryEnabled: boolean,
  selectedTaskId: null | string,
  tasks: [{
    id, profile, title, action, deadline,
    status: "pending" | "done", source, updatedAt
  }],
  expected: {
    decision: "resolved" | "ambiguous" | "none" | "disabled",
    taskId: null | string,
    draft: "required" | "forbidden" | "optional",
    deadline: null | string
  },
  rationale
}
```

- `text` 是本轮发言；`context` 按从旧到新的顺序保存近期发言。`selectedTaskId` 代表本人已经明确选择的事项，不是系统预测。
- `knowledge` 是虚构场景资料，`tasks` 是模拟当事人已确认记录；`source` 仅说明虚构交流来源，不写标签或正确答案。
- `expected` 与 `rationale` 只供评分与人工审阅，不得发送给被测模型。预处理与候选记忆不得使用这些字段。
- `rationale` 解释预设标签的意图，便于后续人工复核；它不代表标签已经通过独立人工验证。
- `decision` 衡量是否以及如何引用已保存事项，与是否新增行动分开评分。取消某事项仍可为 `resolved`，但其行动草稿应为 `forbidden`。
- `resolved` 的 `taskId` 必须属于当前个人档案、同编号的最新有效版本；其他决策的 `taskId` 均为 `null`。
- `required` 表示本轮明确要求记录或更正具体安排；`forbidden` 表示不应生成新增/继续办理行动草稿，包括问句、取消、未满足条件、未消歧和记忆隔离场景。取消请求在这里不作为“继续办理”行动草稿评分，系统如支持结构化取消事件，应另增事件类型指标。
- `optional` 表示本轮只是明确识别议题或沿用已确认安排；生成与否均不因草稿存在性得失分，关联正确性仍评分。
- `expected.deadline` 只表示本轮应明确写入草稿的新期限；未指定新期限时为 `null`。标签保留原文明确表达，例如“周三前”仍标为“周三前”。评分可将“星期三”与“周三”、“周一之前”与“周一前”做等义归一化，同时保留前、后等时间约束。不要把历史事项的日期自动当成本轮新日期。日期正确性应在 required 样本上单列评分。
- 版本样本还应记录实际进入 prompt 的版本，检查较旧记录和其他档案是否被排除；仅靠匹配 `taskId` 无法证明版本正确。

## 公平对照建议

两组使用同一模型版本、温度、输出 schema、原始文本、场景资料、上下文、本人选择，以及相同的档案过滤与版本前处理。直接调用组可一次性获得全部合法最新事项；Agent 组按策略选择相关事项、澄清和约束结果。这样测量的是系统策略增益，不能把访问不同原始资料造成的差异当作算法收益。

应同时报告总体与各类别表现：事项决策正确率、可关联样本召回、错误绑定次数/率、澄清召回、草稿产生精确率与召回、日期正确率。覆盖率、额外澄清和漏关联要一起展示，不能只报告零错误。性能指标另记录真实请求成功率、P50/P95 时延、输入/输出 Token 和重试数，保留失败调用及原始响应。

## 受限之处

1. 场景与预设标签由本次 AI 辅助开发流程构建，尚未经独立人工复核。虽先冻结后运行，仍可能受生成模型偏好及开发流程知晓算法的影响，不属于独立隐藏测试或人工标注的 gold 标准。
2. 只有 60 条短场景，不能证明真实用户、长对话、方言、口音、复杂业务或跨设备场景的总体效果。
3. 该数据衡量文本阶段的记忆关联与草稿行为，不衡量 ASR 质量、手语语言正确率、数字人动作、真实录音豆或端到端翻译延迟。
4. 英文覆盖很少，主要用于检查基本语言和上下文行为，不能宣称多语言能力已充分验证。
5. 医院和银行例子是虚构行政流程，不代表实际机构规则或专业建议。
6. 单次模型输出有随机性；应重复测量并保留所有结果。不能按模型表现事后删除失败题或改变标签。
7. 60 条标签中含明确场景边界，模型可能在常识上选择另一种合理解释；有争议时记录分歧，另建修订版，并保留本版得分。
